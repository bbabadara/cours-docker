🐳 Conteneurisation et Docker

Cours complet : concepts, architecture, manipulations et TP

1. La Conteneurisation

1.1 Qu'est-ce que la conteneurisation ?

La conteneurisation est une technologie qui permet d'empaqueter une application et toutes ses dépendances dans un conteneur isolé, léger et portable.

Un conteneur regroupe :

  • Le code de l'application
  • Les bibliothèques
  • Les fichiers de configuration
  • Les outils système nécessaires

1.2 Les caractéristiques des conteneurs

Flexible

Même les applications les plus complexes peuvent être conteneurisées.

Léger

Les conteneurs exploitent et partagent le noyau hôte (efficaces en ressources vs VM).

Portable

Créer localement, déployer sur le cloud et exécuter n'importe où.

Faible couplage

Conteneurs autonomes et encapsulés (remplacement sans perturber les autres).

Évolutif

Augmenter et distribuer automatiquement des répliques de conteneurs.

Sécurisé

Contraintes et isolements appliqués aux processus sans configuration requise.

1.3 Les limites de la conteneurisation

Isolation moins forte que les VM

Les conteneurs partagent le noyau du système hôte.

Sécurité

Une faille dans le moteur peut affecter tous les conteneurs.

Complexité

Gérer des centaines de conteneurs nécessite Kubernetes.

2. Différence entre Machine Virtuelle et Container

2.1 Machine Virtuelle (VM)

Une VM exécute un système d'exploitation « invité » complet avec un accès virtuel aux ressources de l'hôte via un hyperviseur. Les VM consomment plus de ressources mais offrent une meilleure isolation.

Architecture VM:
┌─────────────────────────────────┐
│        Application A            │
├─────────────────────────────────┤
│        OS Invité (Guest OS)     │
├─────────────────────────────────┤
│     Hyperviseur (VMware, etc.)  │
├─────────────────────────────────┤
│        OS Hôte (Host OS)        │
├─────────────────────────────────┤
│        Infrastructure           │
└─────────────────────────────────┘

2.2 Container

Un conteneur s'exécute nativement sous Linux et partage le noyau de la machine hôte. Il exécute un processus unique, ce qui le rend léger.

Architecture Container:
┌──────────────────┬──────────────────┐
│   Container A    │   Container B    │
│  ┌────────────┐  │  ┌────────────┐  │
│  │ Application│  │  │ Application│  │
│  ├────────────┤  │  ├────────────┤  │
│  │ Biblioth.  │  │  │ Biblioth.  │  │
│  └────────────┘  │  └────────────┘  │
├──────────────────┴──────────────────┤
│      Docker Engine / Runtime        │
├─────────────────────────────────────┤
│      OS Hôte (Kernel partagé)       │
├─────────────────────────────────────┤
│         Infrastructure              │
└─────────────────────────────────────┘

2.3 Comparaison

Critère VM Container
TailleLourde (Go)Légère (Mo)
DémarrageLent (minutes)Rapide (secondes)
OSOS complet invitéPartage le noyau hôte
IsolationForteMoyenne (processus)
PerformanceOverhead importantProche du natif

3. Présentation de Docker

3.1 Qu'est-ce que Docker ?

Docker est une plate-forme open-source permettant de créer, exécuter et partager des applications avec des conteneurs. Écrit en Go, il profite des fonctionnalités du noyau Linux.

3.2 docker-io vs docker-ce

docker-io : version des dépôts officiels Debian/Ubuntu.

docker-ce : version certifiée fournie par docker.com (Community Edition gratuite, Enterprise Edition payante).

On privilégiera docker-ce avec Ubuntu.

3.3 Installation sous Ubuntu

Supprimer une ancienne installation

sudo apt remove docker docker-engine docker.io
sudo snap remove docker

Installation de docker-ce (officiel)

sudo apt update
sudo apt install ca-certificates curl gnupg
sudo install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/ubuntu/gpg | sudo gpg --dearmor
sudo chmod a+r /etc/apt/keyrings/docker.gpg
echo \
  "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] \
  https://download.docker.com/linux/ubuntu \
  $(. /etc/os-release && echo "$VERSION_CODENAME") stable" | \
  sudo tee /etc/apt/sources.list.d/docker.list > /dev/null
sudo apt update
sudo apt install docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

Vérification

systemctl status docker
docker --version
docker --help

Permission (ajouter l'utilisateur au groupe docker)

sudo usermod -aG docker ${USER}
su - ${USER}

3.4 Docker Engine - Architecture

Docker Engine est une application client-serveur avec :

  • Daemon dockerd : processus serveur qui gère les conteneurs
  • CLI docker : interface en ligne de commande
  • REST API : interface pour les programmes
Système à couches :
dockerd (démon) → containerd → runc → kernel Linux (cgroups + namespaces)

3.5 Technologie sous-jacente

Namespaces (espaces de noms)

Isolent l'espace de travail du conteneur : pid, net, ipc, mnt, uts.

Cgroups (groupes de contrôle)

Partagent les ressources matérielles et appliquent des limites et contraintes.

UnionFS

Système de fichiers en couches (AUFS, btrfs, vfs, DeviceMapper) rend les images légères et rapides.

3.6 Un Conteneur = Un processus

Le principe de Docker implique qu'un conteneur représente un seul processus du système. Un processus peut cependant se "forker" en plusieurs processus.

Astuce : Il est possible de contourner ce principe en utilisant un gestionnaire de processus comme supervisord pour gérer plusieurs processus dans le même conteneur.

4. Les composants principaux de Docker

4.1 Image Docker

Une image est un modèle (template) en lecture seule avec des instructions pour créer un conteneur. Souvent basée sur une autre image avec une personnalisation supplémentaire. Chaque instruction d'un Dockerfile crée un calque (layer) dans l'image.

# Lister les images
docker images

# Télécharger une image
docker pull nginx:latest

# Construire une image
docker build -t mon-app:1.0 .

# Rechercher une image
docker search ubuntu
docker search --filter "is-official=true" ubuntu

4.2 Container

Un conteneur est une instance exécutable d'une image. Il est défini par son image et les options de configuration. On peut le connecter à des réseaux, y attacher du stockage, ou créer une nouvelle image depuis son état actuel.

# Créer et démarrer
docker run -d --name mon-nginx nginx

# Mode interactif
docker run -it --name mon-ubuntu ubuntu:16.04 /bin/bash

# Lister les conteneurs
docker ps
docker ps -a

# Exécuter une commande dans un conteneur en cours
docker exec -it mon-nginx sh

# Arrêter / Démarrer
docker stop mon-nginx
docker start mon-nginx

4.3 Dockerfile

Fichier texte contenant les instructions pour construire une image. Chaque instruction crée un calque.

Instruction Description Exemple
FROMImage de base (obligatoire)FROM ubuntu:20.04
RUNExécute une commande pendant la constructionRUN apt-get install -y g++
COPYCopie des fichiers de l'hôte vers le conteneurCOPY . /src/
ADDIdem COPY + extraction auto d'archivesADD . /src/
WORKDIRDéfinit le répertoire courantWORKDIR /src
CMDCommande au démarrage du conteneurCMD ["make", "tests"]
EXPOSEExpose un portEXPOSE 3000
ENVVariable d'environnementENV LANG fr_FR.UTF-8
USERDéfinit l'utilisateurUSER iris
LABELMétadonnéesLABEL maintainer="email"
 
# Exemple Dockerfile complet
FROM ubuntu:20.04
LABEL maintainer="tvaira@free.fr"
ARG DEBIAN_FRONTEND=noninteractive
RUN apt-get update && apt-get install -y g++ make git
RUN rm -rf /var/lib/apt/lists/* /tmp/* /var/tmp/*
COPY . /src/
WORKDIR /src
CMD ["make", "tests"]

4.4 Docker Hub

Registre cloud pour stocker et partager des images Docker. hub.docker.com

docker login
docker tag mon-app:1.0 username/mon-app:1.0
docker push username/mon-app:1.0
docker pull username/mon-app:1.0

4.5 Volume

Les volumes permettent de persister les données en dehors du cycle de vie du conteneur. Syntaxe : VOLUME:CONTAINER_PATH[:ACCESS_MODE]

# Volume nommé
docker volume create mon-data
docker run -d -v mon-data:/data nginx

# Bind mount (dossier local)
docker run -d -v $(pwd):/app nginx

# Volume en lecture seule
docker run -d -v ./config:/app/config:ro nginx

4.6 Network

Docker permet de créer des réseaux pour connecter les conteneurs entre eux.

docker network ls
docker network create mon-reseau
docker run -d --network mon-reseau --name app1 nginx

7. Docker Compose

7.1 Qu'est-ce que Docker Compose ?

Docker Compose est un outil permettant de définir et exécuter des applications à partir de multiples conteneurs. Lorsque plusieurs conteneurs doivent interagir (ex: un serveur web et une base de données), il est indispensable d'utiliser Docker Compose.

La configuration est réalisée dans un fichier docker-compose.yaml (format YAML). Le démarrage est assuré par une commande unique docker compose.

7.2 Instructions principales

Instruction Description Exemple
versionVersion du format YAMLversion: '3'
servicesListe des services (conteneurs)services: web:
imageImage utiliséeimage: nginx:latest
portsMappage de ports [HOST:]CONTAINER- "8080:80"
volumesMontage de volumes- ./app:/app
environmentVariables d'environnementMYSQL_ROOT_PASSWORD: 'pass'
buildConfiguration de constructionbuild: context: ./php

7.3 Exemple : environnement web PHP complet

Étape 1 : Serveur web NGINX

version: '3'
services:
  web:
    image: nginx:latest
    ports:
      - "8080:80"

Le port 80 du conteneur est accessible sur le port 8080 de la machine locale.

Étape 2 : Fichiers du serveur web

version: '3'
services:
  web:
    image: nginx:latest
    ports:
      - "8080:80"
    volumes:
      - ./nginx.conf:/etc/nginx/conf.d/nginx.conf
      - ./app:/app

Étape 3 : PHP-FPM

version: '3'
services:
  web:
    image: nginx:latest
    ports:
      - "8080:80"
    volumes:
      - ./nginx.conf:/etc/nginx/conf.d/nginx.conf
      - ./app:/app
  php:
    image: php:fpm-latest
    volumes:
      - ./app:/app

Étape 4 : MySQL/MariaDB

version: '3'
services:
  web:
    image: nginx:latest
    ports:
      - "8080:80"
    volumes:
      - ./nginx.conf:/etc/nginx/conf.d/nginx.conf
      - ./app:/app
  php:
    build:
      context: ./php
      dockerfile: Dockerfile
    volumes:
      - ./app:/app
  mysql:
    image: mariadb:latest
    environment:
      MYSQL_ROOT_PASSWORD: 'password'
      MYSQL_USER: 'bts'
      MYSQL_PASSWORD: 'password'
      MYSQL_DATABASE: 'bd'
    volumes:
      - mysqldata:/var/lib/mysql
    ports:
      - 3306:3306
volumes:
  mysqldata: {}

Dockerfile pour l'extension PHP PDO MySQL

FROM php:fpm
RUN docker-php-ext-install pdo pdo_mysql

9. Le réseau Docker

9.1 Types de réseaux

Pilote Description
noneAucune interface réseau (sauf loopback) - isolation complète
bridgeRéseau par défaut, conteneurs communiquent entre eux mais pas accessibles de l'extérieur (sauf mappage de ports)
hostUtilise la même interface réseau que la machine hôte - aucune isolation réseau
overlayConnecte plusieurs démons Docker ensemble
ipvlanContrôle sur l'adressage IPv4 et IPv6
macvlanAttribue une adresse MAC à un conteneur

9.2 Le réseau bridge par défaut

L'installation Docker crée un réseau bridge connecté à l'interface docker0 (172.17.0.0/16). Chaque nouveau conteneur est automatiquement connecté à ce réseau.

# Vérifier l'interface docker0
ifconfig docker0
ip addr show docker0

# Lister les réseaux
docker network ls

# Inspecter un réseau
docker network inspect <NETWORK_ID>

9.3 Gestion des réseaux

# Commandes disponibles
docker network COMMAND
  connect     Connecter un conteneur
  create      Créer un réseau
  disconnect  Déconnecter un conteneur
  inspect     Afficher les détails
  ls          Lister les réseaux
  prune       Supprimer les réseaux inutilisés
  rm          Supprimer un réseau

# Créer un nouveau réseau bridge
docker network create --driver bridge mon-reseau \
  --subnet=172.16.0.0/16 --gateway=172.16.0.1

# Lister les réseaux
docker network ls

# Lancer des conteneurs sur le nouveau réseau
docker run -dit --rm --network=mon-reseau --name=conteneur1 alpine
docker run -dit --rm --network=mon-reseau --name=conteneur2 alpine

# Communication entre conteneurs
docker exec conteneur1 ping -c 1 172.16.0.3

# Nettoyage
docker network disconnect mon-reseau conteneur1
docker network disconnect mon-reseau conteneur2
docker network rm mon-reseau

9.4 Options utiles de docker run

--network network    Connecter à un réseau
--add-host list      Mapping host-to-IP personnalisé
--ip string          Adresse IPv4
--ip6 string         Adresse IPv6
--mac-address string Adresse MAC
--user uid:gid       Exécuter avec un utilisateur spécifique
--workdir dir        Répertoire de travail
--volume src:dst     Montage de volume

Partie 2 : Premier pas

Question 7

Rechercher les images alpine officielles. Qu'est-ce qu'"Alpine Linux" ? Quelle est sa principale particularité ? Comparer la taille de l'image "Alpine Linux" avec la taille d'une image "Ubuntu".

docker search --filter "is-official=true" alpine
docker pull alpine:latest
docker images  # comparer les tailles avec ubuntu

Réponse : Alpine Linux est une distribution Linux légère basée sur musl libc et busybox. Sa principale particularité est sa taille minimale (~5 Mo) comparée à Ubuntu (~70-135 Mo), ce qui en fait une base idéale pour des conteneurs optimisés.
